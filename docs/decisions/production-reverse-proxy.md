# Решение: Caddy для HTTPS, раздачи фронта и проксирования API

Дата: 2026-10-23.
Статус: принято.

## Контекст

Stageby разворачивается через Docker Compose на одном VPS с Ubuntu 26.04 LTS, 2 CPU и 4 ГБ RAM. На старте используются один домен приложения, статическая сборка Vite и один backend на Node.js. Файлы раздаются напрямую из внешнего приватного S3 по подписанным HTTPS-ссылкам. Релизы доставляются готовыми образами по SSH; отдельный CI-сервер и динамические preview-окружения не предусмотрены.

Нужен входной веб-сервер, который раздаёт фронт, направляет `/api/...` в backend, управляет HTTPS-сертификатами и выставляет заголовки безопасности. Основной критерий выбора — простота сопровождения этой схемы. Преимущество по производительности или расходу памяти сравнительными замерами не устанавливалось.

Рассмотренные варианты:

| Вариант | Применимость к Stageby | Особенности сопровождения |
| --- | --- | --- |
| Caddy | Раздача статики, reverse proxy и автоматический HTTPS в одном процессе | Конфигурация маршрутов и заголовков, постоянное хранилище сертификатов |
| Nginx | Полностью подходит для той же архитектуры, предоставляет широкие возможности настройки | Конфигурация веб-сервера и автоматизация сертификатов через ACME-модуль либо внешний клиент, например Certbot |
| Traefik | Удобен для динамического подключения множества контейнеров, приложений и preview-окружений | Настройка routers, services, middlewares и certificate resolver; для раздачи файлов фронта обычно нужен отдельный веб-сервер |

## Решение

Использовать Caddy как входной веб-сервер production-развёртывания Stageby.

- Раздавать статическую сборку фронта и проксировать запросы API одним сервисом.
- Использовать встроенное автоматическое получение и продление сертификатов и перенаправление HTTP на HTTPS.
- Хранить маршруты и заголовки в явной конфигурации; доступ к Docker API для обнаружения контейнеров не требуется.
- Настроить маршруты приложения и API, CSP и остальные заголовки безопасности в рамках реализации инфраструктуры.

Для текущей схемы такое сочетание уменьшает число отдельно обслуживаемых компонентов. Автоматический HTTPS — штатная возможность Caddy: [документация](https://caddyserver.com/docs/automatic-https).

Nginx остаётся полноценной альтернативой. Если сопровождение будет выполнять команда с устоявшимися конфигурациями и опытом Nginx, выбор можно пересмотреть. Утверждение, что Nginx обязательно требует Certbot, неверно: доступен официальный открытый ACME-модуль; его установку и конфигурацию необходимо включать в инфраструктуру. См. [модули Nginx Open Source](https://docs.nginx.com/nginx/admin-guide/installing-nginx/installing-nginx-open-source/) и [исходный код nginx-acme](https://github.com/nginx/nginx-acme).

Traefik стоит повторно рассмотреть при появлении нескольких независимо выпускаемых приложений, динамических маршрутов через Docker labels или preview-окружений. Docker provider использует Docker API, доступ к которому нужно защищать. Это не обязательное свойство любого развёртывания Traefik: файловая конфигурация позволяет работать без Docker socket. См. [Docker provider](https://doc.traefik.io/traefik/reference/install-configuration/providers/docker/) и [File provider](https://doc.traefik.io/traefik/reference/install-configuration/providers/others/file/).

## Последствия

- Production-конфигурация и образ фронта используют Caddy; отдельный ACME-клиент в базовой схеме не нужен.
- Данные Caddy, включая сертификаты, должны сохраняться между пересозданиями контейнера. Для выдачи сертификатов нужны корректные DNS-записи и доступность соответствующих ACME challenges.
- Выбор прокси сам по себе не обеспечивает корректные CORS и CSP. Политики приложения и S3, доверенные прокси, cookies и заголовки требуют отдельной настройки и браузерной проверки.
- Решение не подразумевает, что Caddy безопаснее или быстрее альтернатив; основание выбора — соответствие текущей архитектуре и объём сопровождения.
- Замена на Nginx или Traefik потребует изменения входного слоя и управления сертификатами; архитектура БД, бэкапов и доставки релизов при этом сохраняется.
- Реализация и приёмка инфраструктуры ещё не выполнены; принятие решения не означает готовность production-развёртывания.
