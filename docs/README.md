# Документация Stageby

Читайте документы по теме задачи. Эта карта помогает выбрать нужный материал; предварительно читать все разделы не требуется.

## Где что хранить

| Каталог | Содержание | Хранение |
| --- | --- | --- |
| `guides/` | Как выполнить конкретную задачу | Git |
| `rules/` | Требования, предметная модель и правила разработки | Git |
| `templates/` | Шаблоны планов и решений | Git |
| `decisions/` | Принятые решения, контекст и последствия | Git |
| `reports/` | Результаты проверок выпусков и ограничения проверок | Git |
| `plans/` | Общие планы, подпланы и отчёты приёмки текущих циклов | Git до полной приёмки цикла |
| `tmp/plans/` | Локальные черновики планов | Вне Git |
| `tmp/tasks/` | Локальные рабочие материалы задач | Вне Git |

Весь `docs/tmp/` исключён из Git. Создавайте его подкаталоги локально по необходимости; общие требования и принятые решения должны находиться в постоянной документации.

## Текущие планы


Порядок работы с планом:

1. Создайте план в `plans/` по [шаблону](templates/plan.md). Связанные подпланы и отчёт приёмки храните рядом в каталоге цикла.
2. Обновляйте статус и результаты проверок по мере выполнения. Выполненный подплан остаётся до завершения всего цикла.
3. После полной приёмки перенесите полезные требования, инструкции и решения в соответствующие постоянные разделы.
4. Удалите общий план, подпланы и отчёт приёмки цикла, уберите ссылки на них из оставшихся документов и оглавления. Отдельный архив не создавайте: история сохраняется в Git.

## Новые документы

Для всей документации:

- Пишите кратко: правило, действие, ожидаемый результат.
- Сохраняйте естественные фразы и явные действия: «После миграций выполните команду».
  Краткость не должна мешать пониманию.
- Используйте короткие абзацы, списки и таблицы; разделяйте блоки пустыми строками.
- Переносите длинные строки для удобства чтения исходников.
- Не повторяйте сведения: оставляйте ссылку на основной документ.
- Убирайте рассуждения и очевидные пояснения, сохраняйте ограничения и критерии проверки.

Используйте понятные имена файлов в `kebab-case`. Имена существующих документов сохранены при переносе. Для новых принятых решений используйте [шаблон решения](templates/decision.md); для планов — [шаблон плана](templates/plan.md).

При добавлении или переносе документа обновляйте эту карту и ссылки на него. Если документ нужен агенту для определённого типа задач, добавьте точечную ссылку в соответствующий `AGENTS.md`, сохраняя чтение по теме задачи.
