## Проверки

Первый `pnpm run check` до реализации прошёл сборку контракта, API lint и проверку типов,
но остановился до выполнения тестов: подключение к PostgreSQL из ограниченного окружения
вернуло `ECONNREFUSED`. Этот запуск не дал полного baseline.
`pnpm run db:up` также не смог подключиться к Docker Engine, включая повтор с разрешёнными правами.
Уже доступные локальные сервисы удалось использовать при запуске тестов с разрешённым доступом.

Фаза 0 закрыта повторной проверкой именно исходной ревизии `4b178f7`, без изменений
реализации edited.ver2. Для этого `git archive` экспортировал ревизию в отдельный каталог
в системной временной папке. Зависимости скопированы из локальной установки в независимые
каталоги; локальные `.env` использовались только для доступа к сервисам и не включены в Git.
`pnpm run check` выполнен с разрешённым доступом к PostgreSQL/MinIO и завершился с кодом 0.

Для воспроизведения: создать отдельную копию ревизии `4b178f757336bb14173efefc5986a27cc5a75c3f`,
подготовить зависимости по lockfile во всех четырёх каталогах (корень, `contracts`, `api`, `web`),
передать локальную конфигурацию PostgreSQL/MinIO и выполнить из корня копии `pnpm run check`.
API-тесты самостоятельно создают временные БД и удаляют их после проверки.

После изменений API-тесты прошли: 23 файла, 109 тестов. Включены чистая БД, повторное применение
миграций и обновление с 0012 до 0013. Каждый запуск использует отдельные временные БД;
рабочая БД не очищалась, миграция на неё не применялась. Web: 6 файлов, 26 тестов,
lint, проверка типов и сборка прошли. API-сборка и генерация также прошли.
Итоговый `pnpm run check` после исправления двух ошибок словаря в новых документах завершился
успешно: контракт, lint, проверки типов, API/web-тесты и обе сборки. Новая заметка проверена
отдельно после записи результатов.

Первый lint нормализовал 30 API-файлов, но проверка Git не выявила содержательных изменений

## Решение об отсутствии переноса данных

Пользователь 04.10.2026 разрешил не сохранять старые данные: приложение ещё не запущено
в production. Подготовка старого набора, перенос счетов/выплат/аудита и переходный период
совместимости отменены. Поддержка прежних этапов с >10 счетами и файлов счетов >10 МиБ
не требуется. В дальнейшем допустим сброс локальных данных при смене модели.
Сброс в этой задаче не выполнялся, рабочая БД и файлы не удалялись.

Граничные случаи новой модели сохраняются: 0/1/10 счетов, отказ для 11-го и конкурентные
запросы, ограничения файлов, оплата/доставка, нехватки, индивидуальные чек-листы и аудит новых
операций. Их проверки остаются в фазах 1–4. Существующие исторические тесты не удалены:
они продолжили проходить в baseline и могут быть пересмотрены при смене схемы.
