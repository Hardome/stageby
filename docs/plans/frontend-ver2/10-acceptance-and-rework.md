## Изменения

- [x] Приёмку подтверждать через `acceptStage` с актуальной версией, без файла акта и реквизитов.

## API и интерфейсы

`acceptStage`, `returnStageForRework`, существующее чтение этапа и объекта. Для доработки передать актуальную версию этапа, комментарий, уникальные ID выбранных пунктов и срок.

## Проверки и критерии готовности

- [x] Приёмка без акта, конфликт версии, повторная отправка — Vitest и браузер с подменёнными ответами API.
- [x] Доработка без комментария/пунктов, срок по умолчанию и заданный срок — Vitest; в браузере проверены валидация и изменение даты.
- [x] Повторное выполнение только возвращённых пунктов — клиентские тесты доступа и интеграционные тесты API `stages`; сквозной цикл с новым фото пройден с настоящим API в плане 11.
- [x] Последний этап выплачен раньше предыдущих — объект остаётся активным. Подтверждено интеграционными тестами API `projects` и `dashboard` на временной PostgreSQL БД; отдельный браузерный прогон этого порядка выплат не проводился.
- [x] Дополнительный этап возвращает объект в активные; его выплата завершает объект повторно — проверено через настоящий HTTP API на объекте №15 в плане 11.
- [x] Решение и замечания обновляются у мастера при открытии или обновлении — проверено при повторном входе мастером и доработке с новым фото в Chromium с настоящим API.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
