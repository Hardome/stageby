# Хранение аудита

Журнал начинает накапливаться после миграции `0012`. Предыдущие изменения не восстанавливаются.
API чтения и интерфейс истории пока отсутствуют; HTTP-контракт не меняется.

## События и изменения

`audit_events` хранит одну успешную операцию: время, код операции, источник (`api`, `command`,
`system`), идентификатор запроса, ID автора и снимок его имени, логина и роли.
Для HTTP код совпадает с OpenAPI `operationId`. Начальная версия формата — `1`.

`audit_changes` хранит изменения внутри события: имя таблицы как стабильный `entityType`,
JSON-объект первичного ключа, ID проекта и этапа при наличии связи, действие и снимки до/после.
Составные ключи сохраняются полностью. При создании `before` равен `null`, при удалении
`after` равен `null`. Повторные изменения одной записи внутри операции объединяются.

ID автора, проекта и этапа не имеют внешних ключей: удаление исходных данных сохраняет историю.
Единственный внешний ключ журнала связывает изменение с событием и запрещает удаление события,
имеющего изменения. Код приложения использует только вставки в журнал; автоматической очистки нет.

## Добавление операции

Маршрут создаёт `requestAuditContext(request)` из авторизации и передаёт его через сервис в
репозиторий. Команды и автоматическая очистка передают явный контекст без автора. Прямые вызовы
репозиториев без контекста используют источник `system`; для новых рабочих вызовов указывайте
контекст явно.

Репозиторий использует `auditedTransaction(database, context, operation, callback)` вместо обычной
транзакции. Внутри callback:

- Вставку с полным `returning()` передают в `audit.created(table, rows)`.
- Изменение или удаление выполняют через `audit.mutate(table, where, write)`: строки читаются
  под блокировкой `FOR UPDATE`, затем выполняется запись и читается результат по первичным ключам.
- Все косвенные изменения передают тому же `AuditWriter`, включая версии, чек-листы,
  связи приёмки и автоматические переходы этапов.
- Для смены пароля вызывают `audit.recordEvent()`, чтобы сохранить событие без снимков секретов.

После callback `append(transaction, context, operation, changes)` вставляет событие и изменения
в ту же транзакцию. Ошибка журнала откатывает предметные данные. Откат операции не оставляет
события. Чтения, ошибки, записи без изменений и идемпотентные повторы событий не создают;
изменение версии считается изменением.

Разрешённые поля явно перечислены в `api/src/modules/audit/snapshots.ts`. Новые поля схемы
автоматически в журнал не попадают. Даты преобразуются в ISO, bigint — в десятичные строки.
Пароли, хеши, сессии, токены, ключи идемпотентности, ключи хранилища, подписанные URL и содержимое
файлов не сохраняются. При изменении формата снимков требуется отдельное решение о версии формата.

Существующая предметная история приёмки сохраняется вместе с общим аудитом. Действия с S3
не входят в транзакцию PostgreSQL: журнал отражает зафиксированное состояние БД. Прямой SQL
вне репозиториев не записывается в журнал. При появлении новых операций нужно явно подключать их запись
и проверять полный путь от HTTP до БД, включая побочные изменения и откат.
