# 06. Рабочий чек-лист

[Подготовка и фиксация результатов](README.md). Нужен назначенный А этап с двумя невыполненными пунктами и фото; для проверок режимов — этапы на приёмке и доработке. Состав чек-листа редактируется в [объекте](03-projects.md).

- [ ] CHK-01. Откройте рабочий список → названия и порядок соответствуют сохранённому составу, есть подсказки и состояния фото, прогресс 0% при отсутствии выполнения.
- [ ] CHK-02. Попробуйте выполнить пункт без успешно загруженного фото, с фото только в очереди и с ошибкой загрузки → выполнение не сохраняется.
- [ ] CHK-03. Загрузите фото и уйдите без «Готово», затем вернитесь → фото сохранено, пункт не выполнен, прогресс не увеличен.
- [ ] CHK-04. Нажмите «Готово» у первого из двух пунктов → он выполнен, прогресс 50%, этап становится `in_progress`, установлена фактическая дата старта.
- [ ] CHK-05. Снимите выполнение и выполните повторно → прогресс пересчитан, первоначальная фактическая дата старта не сброшена и не заменена новой.
- [ ] CHK-06. На отдельном чек-листе из трёх пунктов выполните один и два → прогресс округлён до 33% и 67%. Пустой чек-лист не должен позволять переход на приёмку; подготовка такого состояния — только тестовой фикстурой.
- [ ] CHK-07. Выполните последний пункт → прогресс 100%, этап переходит в `acceptance`; карточка этапа и списки обновлены после ответа.
- [ ] CHK-08. Как А на приёмке попытайтесь менять пункты/фото → режим чтения, серверные ограничения нельзя обойти старой вкладкой.
- [ ] CHK-09. После возврата на доработку откройте список → замечания и общий срок видны; менять можно только возвращённые пункты, остальные сохраняют результат.
- [ ] CHK-10. Повторное выполнение возвращённого пункта со старым фото → требуется новое успешно загруженное фото. После него и явного «Готово» пункт принимается как выполненный.
- [ ] CHK-11. Удалите последнюю фотографию выполненного пункта с подтверждением → выполнение и прогресс снимаются вместе; при отмене подтверждения оба остаются прежними.
- [ ] CHK-12. Инженер запускает очистку фото по сроку на тестовой фикстуре → исчезновение файла не снимает историческое выполнение, прогресс и статус; интерфейс объясняет отсутствие фото.
- [ ] CHK-13. В двух вкладках измените один пункт → устаревшее действие получает конфликт, не перетирает актуальное состояние; после обновления показан единый результат.
- [ ] CHK-14. При выполнении оборвите сеть → нет ложного успеха; после восстановления и обновления видно фактическое серверное состояние, повтор не создаёт противоречивый прогресс.
