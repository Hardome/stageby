# 02. Управление пользователями

[Подготовка и фиксация результатов](README.md). Все изменения выполняет Р на тестовых учётных записях. Для проверки отзыва доступа держите сессию А открытой отдельно.

## Список и поиск

- [ ] USR-01. Откройте пользователей → отображаются актуальные имена, логины, роли и активность; пароль не показывается.
- [ ] USR-02. Найдите пользователя, примените фильтр роли и активности → список соответствует условиям; пустой результат отличается от ошибки загрузки.
- [ ] USR-03. Перейдите на следующую страницу, обновите браузер и вернитесь назад → фильтры и позиция списка восстанавливаются из URL; смена фильтра не оставляет пустую старую страницу.
- [ ] USR-04. Откройте ссылку с некорректными параметрами поиска/пагинации → приложение не падает, использует безопасные значения.

## Создание и изменение

- [ ] USR-05. Создайте мастера с именем, уникальным логином, ролью, паролем и подтверждением без телефона → запись сохраняется, вход нового пользователя работает.
- [ ] USR-06. Повторите с телефоном и ролью руководителя → значения сохраняются и права соответствуют роли.
- [ ] USR-07. Попробуйте пустое/пробельное имя, пустые обязательные поля, несовпадающие пароли и занятый логин → есть понятные ошибки, дубль не создаётся, допустимый ввод не теряется.
- [ ] USR-08. Заполните форму, уйдите и вернитесь в рамках разрешённого черновика → несекретные поля восстанавливаются, пароль и подтверждение отсутствуют.
- [ ] USR-09. Измените имя, телефон и роль тестового пользователя, затем очистите необязательный телефон → после обновления показаны новые значения; старые сведения в списке не остаются.
- [ ] USR-10. Р изменяет роль открытого пользователя → при следующем обновлении прав доступны только действия новой роли; изменение нельзя обойти старой вкладкой.
- [ ] USR-11. Отключите А при открытой сессии А → следующий запрос требует входа; вход А выдаёт нейтральную ошибку. Включите А снова → вход разрешён, отозванная сессия сама не оживает.

## Пароль и отказы

- [ ] USR-12. Назначьте новый пароль с несовпадающим подтверждением → сохранения нет. Исправьте → пароль меняется, прежние сессии отзываются.
- [ ] USR-13. Создайте публичный запрос сброса, назначьте пароль → отметка исчезает в карточке и списке, новый пароль работает.
- [ ] USR-14. При сохранении отключите сеть → форма сохраняет допустимый ввод, успех не показывается; после восстановления доступен повтор.
- [ ] USR-15. Отправьте форму двойным нажатием → создаётся одна запись. После изменения пользователя вернитесь в список → видны актуальные значения.
- [ ] USR-16. Как А откройте формы создания, редактирования и пароля по прямым ссылкам → данные недоступны, действия не выполняются.
