# 01. Доступ, сессия и сброс пароля

[Подготовка и фиксация результатов](README.md). Нужны Р, А, Б, отключённый пользователь и ссылка на этап А. Для проверок черновиков используйте один браузер, для независимых ролей — отдельные профили.

## Вход и маршруты

- [ ] AUTH-01. Войдите как Р → открывается дашборд. Войдите как А → открывается «Мои этапы»; после обновления роль и главная сохраняются.
- [ ] AUTH-02. Отправьте пустые поля входа → видны связанные с полями ошибки, вход не выполняется. Исправьте значения → форму можно отправить повторно.
- [ ] AUTH-03. Проверьте неверный пароль, неизвестный логин и отключённый аккаунт → одинаковое сообщение «Неверный логин или пароль.», без раскрытия существования или блокировки пользователя.
- [ ] AUTH-04. Без сессии откройте прямую ссылку на разрешённый этап с параметрами → после входа откроется исходная внутренняя страница с параметрами, а не произвольная главная.
- [ ] AUTH-05. Подставьте во входной адрес возврата внешний URL, `//example.com` и страницу входа → перехода на сторонний сайт и цикла входа нет.
- [ ] AUTH-06. Как А откройте прямые ссылки на пользователей, объект руководителя и этап Б; затем неизвестный URL → нейтральная «404 — Страница не найдена», без данных или объяснения существования чужого ресурса.
- [ ] AUTH-07. Как Р откройте страницы мастера → доступ разрешён. Наличие либо отсутствие пункта меню не заменяет проверку прямой ссылки.
- [ ] AUTH-08. Сделайте несколько быстрых отправок входа → интерфейс показывает ожидание и не создаёт параллельные действия. При достижении лимита есть понятная ошибка и возможность повторить позже.

## Выход, отзыв сессии и черновики

- [ ] AUTH-09. Выйдите, затем нажмите «Назад» и обновите защищённую страницу → рабочие данные не доступны, нужен вход.
- [ ] AUTH-10. Истеките или отзовите сессию А во время работы → следующий защищённый запрос отправляет на вход, прежний защищённый кэш очищается, причина блокировки аккаунта не раскрывается.
- [ ] AUTH-11. При незавершённой форме и очереди фото истеките сессию; войдите тем же пользователем → допустимый черновик и очередь восстанавливаются, пароль не восстанавливается и не хранится в черновике.
- [ ] AUTH-12. После явного выхода войдите как Б → черновиков, очереди и результатов запросов А нет. Повторите смену пользователя после истечения сессии → данные А также не доступны Б.
- [ ] AUTH-13. Подготовьте черновик формы, успешно сохраните её и откройте создание заново → сохранённая форма не возвращается как незавершённый черновик.

## Запрос нового пароля

- [ ] AUTH-14. Запросите сброс для активного, неизвестного и отключённого логина → одинаковое публичное подтверждение; письмо или самостоятельная смена пароля не обещаются.
- [ ] AUTH-15. Запросите сброс для А, затем повторите → у Р видна одна актуальная отметка в списке/карточке пользователя; повтор не создаёт дублирующихся запросов.
- [ ] AUTH-16. Р назначает А новый пароль → отметка запроса исчезает, старый пароль больше не подходит, новый работает, прежние сессии А отозваны.
- [ ] AUTH-17. Заблокируйте сеть во время запроса сброса → успех не показывается до ответа; после восстановления запрос можно повторить без зависшей формы.
