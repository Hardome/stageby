# 10. Приёмка, доработка и завершение

[Подготовка и фиксация результатов](README.md). Нужны Р и А, этап на приёмке с двумя выполненными пунктами и фото, отдельные этапы с планами 10 000 ₽, 0 и без плана. Для повторных проверок используйте отдельные копии объектов.

## Решение руководителя

- [ ] ACC-01. Как А выполните все пункты → этап на приёмке, пункты доступны А только для чтения. Как Р откройте приёмку → можно просмотреть пункты и фото и принять решение.
- [ ] ACC-02. Как мастер попробуйте прямой переход/старую форму принятия или возврата → решение не сохраняется; права проверяются сервером.
- [ ] ACC-03. Как Р примите этап без загрузки акта → приёмка успешна, показаны решение, автор и дата, фактическое окончание установлено сервером.
- [ ] ACC-04. Примите этап с планом 10 000 и выплатой 3 000 → `completed`. С полной выплатой → `paid`; с планом 0 → `paid`; без плана → `completed`.
- [ ] ACC-05. Полностью оплатите ещё не принятый этап → это не заменяет приёмку и не завершает этап.

## Возврат и повторная приёмка

- [ ] ACC-06. Выберите один из двух пунктов, введите индивидуальное замечание и общий срок → этап `rework`, только выбранный пункт требует повторного выполнения; невыбранный результат сохранён.
- [ ] ACC-07. Откройте форму возврата → срок по умолчанию Т+2 по Екатеринбургу. Попробуйте вчера, пустой срок, отсутствие выбранных пунктов и пустое/пробельное замечание → форма не сохраняется.
- [ ] ACC-08. Как А откройте доработку → видны замечания к нужным пунктам, срок, автор/дата решения; правка остальных пунктов запрещена.
- [ ] ACC-09. Попробуйте выполнить возвращённый пункт только со старым фото → нельзя. Добавьте новое фото, уйдите без «Готово» → доработка ещё не выполнена; нажмите «Готово» → результат обновляется.
- [ ] ACC-10. Верните несколько пунктов; выполните только часть → этап остаётся на доработке. Выполните все → снова `acceptance`, затем Р может принять его.
- [ ] ACC-11. При повторной приёмке проверьте отображение последнего решения на этапе и в рабочем чек-листе; первоначальная дата старта не заменена датой доработки.
- [ ] ACC-12. В двух вкладках одновременно примите/верните один этап → сохраняется согласованный результат, устаревшее действие сообщает конфликт без ложного второго решения.

## Завершение объекта

- [ ] ACC-13. Оплатите последний по позиции этап, оставив ранний невыплаченным → объект не `completed`, на дашборде остаётся первый невыплаченный.
- [ ] ACC-14. Доведите все включённые этапы до `paid` → объект завершён, активный счётчик уменьшился; исключённые этапы не мешают завершению.
- [ ] ACC-15. На выплаченном принятом этапе увеличьте план или уменьшите факт выплат → этап `completed`, объект снова не завершён; принятие и фактические даты сохранены.
- [ ] ACC-16. К завершённому объекту добавьте дополнительный этап → объект снова активен; после выполнения, приёмки и расчёта нового этапа снова завершается.
- [ ] ACC-17. При ошибке сети во время решения → введённые замечания не теряются, повтор возможен; перед повтором после потери ответа обновите фактическое состояние. После успешного решения списки и сводки согласованы.

- [ ] ACC-18. Как Р попробуйте принять этап без назначенного мастера через API с актуальной версией → assignee_required, решение и статус не меняются.
