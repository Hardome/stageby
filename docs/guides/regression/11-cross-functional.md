# 11. Общие проверки и сквозной регресс

[Подготовка и фиксация результатов](README.md). Нужны реальный API/S3, обе роли, браузерные инструменты для отказов, реальные Android и iPhone. Эмуляция размера окна не заменяет камеру, HEIC и установленный ярлык.

## Состояния, конкурентность и изоляция

- [ ] GEN-01. На списках, карточках и формах замедлите сеть → загрузка отличима от пустого результата, статические подписи доступны; фоновые запросы не размонтируют форму и не уничтожают ввод.
- [ ] GEN-02. Последовательно вызовите offline, ошибку API и недоступность S3 → понятна проблема и доступен повтор, сообщение об успехе не появляется без подтверждения; исправные независимые блоки продолжают работать.
- [ ] GEN-03. При обновлении списка/расчёта предыдущие данные не воспринимаются как новый ответ; фильтры и повтор остаются доступны, повторная пагинация не перемешивает ответы.
- [ ] GEN-04. На объекте, выплате, счёте, выполнении пункта и приёмке проверьте устаревшее сохранение из второй вкладки → конфликт не перетирает новую запись, пользователю предлагается обновить состояние с сохранением полезного ввода.
- [ ] GEN-05. Для основных форм нажмите отправку несколько раз, затем обновите страницу → нет дублирующихся сущностей, зависшего ожидания и ложного завершения. Потерю ответа проверяйте отдельно от отказа до отправки.
- [ ] GEN-06. Измените ID объекта, этапа, пункта, файла и счёта в прямой ссылке на чужой ресурс → данные не раскрываются; `403`/`404` при загрузке страницы ведут к одной нейтральной заглушке.
- [ ] GEN-07. Отзовите сессию/назначение при открытой форме → следующее действие не меняет защищённые данные; после другого входа старый кэш и локальные черновики не видны.
- [ ] GEN-08. Обновите прямые ссылки на объект, этап, вкладку, фото и страницу списка с параметрами → нет серверного 404 из-за SPA-маршрута, открывается правильный экран или вход с безопасным возвратом.
- [ ] GEN-09. На HTTPS-окружении проверьте фото, PDF и все формы с DevTools → нет блокировки нужных ресурсов политиками CSP/CORS и mixed content. При наличии production-политик проверьте недопустимый Origin с инженером; localhost-проверка этого не заменяет.

## Матрица интерфейса

Для полного прогона пройдите вход, пользователей, дашборд, создание/редактирование объекта, список мастера, этап, чек-лист, фото, выплаты, материалы и приёмку в обеих темах на ширинах 390, 768, 1024 и 1440 px. Повторяйте ролевые ограничения для соответствующей роли; отмечайте конкретный экран и комбинацию при ошибке.

- [ ] UI-01. На каждой комбинации нет обрезанных кнопок, перекрывающихся текстов, недоступных действий и непредусмотренного горизонтального скролла; длинные адреса/имена/комментарии не ломают экран.
- [ ] UI-02. В светлой и тёмной теме читаются обычный текст, ошибки, суммы, disabled-состояния и предупреждения; значение индикатора понятно не только по цвету.
- [ ] UI-03. Пройдите формы клавиатурой → порядок Tab логичен, фокус видим, Enter не вызывает неожиданного сохранения, Escape и закрытие диалога возвращают управление ожидаемому элементу.
- [ ] UI-04. Ошибка формы относится к нужному полю; после неуспешного сохранения поле можно найти, исправить и отправить без повторного заполнения всей формы.
- [ ] UI-05. На реальном телефоне экранная клавиатура не скрывает ошибку и сохранение; диалоги и просмотр фото работают в портретной и альбомной ориентации, прокрутка доступна.
- [ ] UI-06. Увеличьте масштаб браузера до 200% → основные сведения и действия остаются доступны; элементы имеют понятные подписи, иконки действий различимы без угадывания.

## Реальные устройства и ярлык

Ориентир установки: [инструкция ярлыка](../install-shortcut.md). Для каждого устройства записывайте модель и версии ОС/браузера, а не только «мобильный браузер».

- [ ] MOB-01. На Android Chrome установите ярлык с HTTPS-сайта и запустите его → правильные имя/иконка, открывается `/`, главная соответствует роли; при отдельном хранилище разрешён повторный вход.
- [ ] MOB-02. Повторите установку через Safari → «На экран Домой» на iPhone; запуск, вход и навигация работают без элементов, скрытых системными областями.
- [ ] MOB-03. В браузере и из установленного ярлыка выполните реальную съёмку, выбор галереи, множественный выбор и HEIC из [проверок фото](07-photos.md).
- [ ] MOB-04. На телефоне оборвите интернет во время загрузки, вернитесь в тот же пункт и повторите → допустимая очередь восстанавливается в том же контексте; закрытое приложение не обещает фоновую отправку.
- [ ] MOB-05. Откройте прямую ссылку на свой этап с истёкшей сессией → после входа сохранён адрес возврата; ссылка чужого этапа не даёт доступ. Основной установленный ярлык по-прежнему запускается с `/`.

## Полный цикл обеими ролями

Используйте новый объект с двумя этапами и изначально известными планами; даты проекта охватывают Т и Т+2. Все шаги выполняйте последовательно, после каждого проверяйте серверный результат обновлением страницы.

- [ ] E2E-01. Р создаёт объект с PDF и двумя непустыми чек-листами, назначает А на оба этапа → объект и этапы видны Р, А видит назначения без доступа к общей карточке объекта.
- [ ] E2E-02. Р добавляет счёт, отмечает частичную оплату; А отмечает доставку и сообщает нехватку → план не меняется, факт и индикаторы отражают фактическую оплату/нехватку на всех экранах.
- [ ] E2E-03. Р устраняет нехватку и доводит оплату счёта до полной → материалы зелёные при полной доставке; изменение счёта не заменяет оплату работ.
- [ ] E2E-04. А загружает фото и уходит без выполнения → фото сохранено, прогресс прежний; после явного выполнения пунктов этап в работе, затем на приёмке.
- [ ] E2E-05. Р возвращает один пункт с замечанием и сроком; А добавляет новое фото и выполняет его → повторная приёмка доступна, остальные пункты не сброшены.
- [ ] E2E-06. Р принимает первый этап и выплачивает плановую сумму → этап `paid`, дашборд выбирает следующий; объект пока не завершён.
- [ ] E2E-07. До окончания второго этапа Р делает выплату А, переназначает этап Б и создаёт выплату Б → старый получатель сохранён, А теряет доступ, Б видит только свою историю, сводка учитывает обоих.
- [ ] E2E-08. Б завершает второй этап, Р принимает и закрывает расчёт → все этапы `paid`, объект завершён, активный счётчик и финансы согласованы.
- [ ] E2E-09. Р добавляет дополнительный этап → объект снова активен; после его выполнения, приёмки и расчёта объект снова завершён.
- [ ] E2E-10. Выйдите, войдите другой ролью и обновите прямые ссылки → нет чужих очередей/черновиков и утечки защищённых данных. В отчёте отдельно перечислены непройденные мобильные и инфраструктурные проверки.
