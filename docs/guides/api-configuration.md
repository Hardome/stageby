# Конфигурация API и файлового хранилища

При общей подготовке `pnpm run bootstrap` создаёт `api/.env` из
[.env.example](../../api/.env.example), если файла ещё нет. При ручной подготовке скопируйте пример
самостоятельно. Существующий `.env` не перезаписывается; изменения настроек требуют перезапуска API.

Сервер читает окружение и `.env` из рабочего каталога `api`. Фактические обязательность,
ограничения и значения при отсутствии переменных определены в
[схеме конфигурации](../../api/src/config/env.ts). В таблицах ниже приведены локальные значения из
примера; они не всегда совпадают с defaults схемы.

## Сервер, БД и доступ браузера

| Переменная | Локальное значение | Назначение |
| --- | --- | --- |
| `NODE_ENV` | `development` | Режим: `development`, `test`, `production` |
| `HOST` | `127.0.0.1` | Адрес прослушивания |
| `PORT` | `3001` | Порт API |
| `LOG_LEVEL` | `debug` | Уровень логирования |
| `DATABASE_URL` | См. `.env.example` | Подключение к PostgreSQL |
| `CORS_ORIGIN` | `http://localhost:3000` | Разрешённые origins браузера через запятую |
| `API_PUBLIC_ORIGIN` | `http://127.0.0.1:3001` | Доверенный публичный origin API/Swagger UI, без пути и завершающего `/` |
| `TRUST_PROXY` | Пусто | Доверенные IP/CIDR reverse proxy через запятую; без значения forwarded-заголовки не используются |

Указывайте origins с протоколом и портом, без пути. При доступе через туннель следуйте
[инструкции демо](local-demo.md).

## Ограничения запросов и сессии

| Переменная | Локальное значение | Назначение |
| --- | --- | --- |
| `RATE_LIMIT_MAX` | `100` | Максимум запросов за окно |
| `RATE_LIMIT_TIME_WINDOW` | `1 minute` | Окно общего ограничения |
| `LOGIN_RATE_LIMIT_MAX` | `5` | Лимит попыток входа отдельно для IP и логина |
| `LOGIN_RATE_LIMIT_TIME_WINDOW` | `1 minute` | Окно ограничения входа; используется также публичным запросом сброса с отдельными счётчиками |
| `SESSION_TTL_HOURS` | `12` | Срок сессии, допустимо 1–12 часов |
| `SESSION_CLEANUP_INTERVAL_SECONDS` | `3600` | Интервал очистки истёкших сессий; до 1000 записей за попытку |

Счётчики ограничений запросов хранятся в памяти процесса. Для нескольких экземпляров API потребуется
общее хранилище счётчиков. Чтобы за прокси различались клиентские IP, задавайте в `TRUST_PROXY`
только адреса реальных доверенных прокси.

## S3

Локально используется MinIO из `compose.yaml`, во внешнем окружении — совместимое приватное
S3-хранилище. Браузер обращается к нему напрямую по подписанным ссылкам: endpoint должен быть
доступен и API, и устройству пользователя. Для HTTPS-приложения нужен HTTPS endpoint файлов.

| Переменная | Локальное значение | Назначение |
| --- | --- | --- |
| `S3_ENDPOINT` | `http://127.0.0.1:9000` | Endpoint S3 API |
| `S3_REGION` | `us-east-1` | Регион подписи запросов |
| `S3_BUCKET` | `stageby` | Приватный bucket приложения |
| `S3_ACCESS_KEY_ID` | См. `.env.example` | Ключ доступа |
| `S3_SECRET_ACCESS_KEY` | См. `.env.example` | Секрет ключа |
| `S3_FORCE_PATH_STYLE` | `true` | Адресация bucket в пути; настройка зависит от провайдера |
| `S3_CREATE_BUCKET` | `true` | Проверить bucket и создать при отсутствии; при выключении bucket готовится отдельно |
| `S3_SIGNED_URL_TTL_SECONDS` | `900` | Срок подписанных ссылок, 60–3600 секунд |
| `FILE_CLEANUP_INTERVAL_SECONDS` | `86400` | Интервал фоновой очистки файлов |

В `NODE_ENV=production` endpoint, регион, bucket и оба ключа обязательны. Без явного
`S3_CREATE_BUCKET` автоматическое создание включено только в development. Локальные credentials из
примера используйте только для разработки и локального демо. Для стороннего хранилища настройте CORS
bucket под origin приложения и необходимые операции прямой загрузки; API CORS не заменяет CORS S3.

## Авторизация и источник запроса

<!-- cspell:ignore Referer -->

`POST /auth/login` устанавливает `stageby_session`: `HttpOnly`, `Path=/`, `SameSite=Lax`, в
production — `Secure`. Браузерные запросы используют `credentials: include`. Токен не возвращается
в JSON и не хранится в `localStorage` /`sessionStorage`.

Все запросы кроме `GET`, `HEAD`, `OPTIONS`, включая вход и запросы из командной строки, должны
передавать доверенный `Origin` либо, при его отсутствии, `Referer`. Источник сверяется с
`CORS_ORIGIN` и `API_PUBLIC_ORIGIN`; `Host` разрешения не даёт. Отсутствующий, некорректный или
`null` источник приводит к `403`. Все ответы API, включая ошибки, получают
`Cache-Control: no-store`.

При использовании Swagger UI на публичном адресе API задайте `API_PUBLIC_ORIGIN` явно:
автоматическое локальное значение применяется только вне production. Признак `Secure` требует HTTPS
при входе; команда `start` режим окружения не выбирает.

## Первый руководитель без интерактивного ввода

После миграций команда `pnpm --dir api run admin:create-first-manager` из корня создаёт руководителя
только при пустой таблице `users`. Для автоматического запуска задайте одновременно
`FIRST_MANAGER_LOGIN`, `FIRST_MANAGER_PASSWORD`, `FIRST_MANAGER_FULL_NAME`; подключение берётся
из `DATABASE_URL`. Не сохраняйте секреты в Git.
