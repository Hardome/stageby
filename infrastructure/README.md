# Инфраструктура Stageby

Здесь находятся файлы Docker для разработки, локальной проверки production-сборки
и будущего развёртывания на VPS. Команды выполняйте из корня репозитория.

## Структура

| Путь | Назначение |
| --- | --- |
| `../compose.yaml` | PostgreSQL и MinIO для обычной разработки |
| `minio/Dockerfile` | Сборка MinIO для разработки и временных тестов |
| `production/build/` | Сборка образов приложения и manifest схемы БД |
| `production/runtime/` | Compose приложения и конфигурация Caddy |
| `production/runtime/env/` | Примеры переменных окружения без секретов |
| `production/migrations/` | Запуск миграций в отдельном контейнере |
| `production/checks/` | Полный прогон проверок в Linux с временными PostgreSQL и MinIO |
| `production/release/` | Проверка происхождения, сборка и упаковка комплекта релиза |
| `production/server/` | Первичная подготовка конфигурации на VPS |

Команды с компьютера разработчика реализованы в
[`scripts/production.mjs`](../scripts/production.mjs) и
[`scripts/production-smoke.mjs`](../scripts/production-smoke.mjs).
Команда сборки комплекта находится в [`scripts/release.mjs`](../scripts/release.mjs).

## Какое окружение использовать

Для обычной разработки запускайте `pnpm run db:up` и `pnpm run dev`.
Корневой Compose сохраняет локальные данные PostgreSQL и MinIO.

Для проверки будущего выпуска используйте:

| Команда | Что делает |
| --- | --- |
| `pnpm run production:check` | Проверяет код в Linux с отдельными тестовыми сервисами |
| `pnpm run production:build` | Собирает образы API, Web/Caddy и мигратора с тегом `local` |
| `pnpm run production:smoke` | Запускает собранные образы и проверяет их совместную работу |
| `pnpm run release:test` | Проверяет защитные проверки и упаковку на временных Git-репозиториях |
| `pnpm run release build` | Собирает комплект из чистого итогового коммита PR в `main` |

В `production:check` генерация выполняется в Linux перед проверками. Generated-файлы
пересоздаются из исходников; отдельно контролируются изменения рукописного кода.

Выполняйте эти команды последовательно. Не запускайте сборку или smoke-стенд
одновременно с `production:check`, чтобы они не отбирали CPU у тестов.

Временные группы `stageby-check-…` и `stageby-smoke-…` удаляются после проверки
вместе с тестовыми данными. Флаг `--keep` у smoke-сценария сохраняет успешный стенд
для отдельной браузерной проверки; после неё стенд нужно удалить вручную.

## Что будет работать на VPS

Постоянно запускаются Web/Caddy, API и PostgreSQL. Контейнер мигратора запускается
на время установки или обновления схемы и затем завершается. MinIO на VPS не нужен:
приложение использует внешний S3.

Команды `production:*` и `release build` выполняются на компьютере разработчика.
На VPS по SSH будут передаваться готовые образы. Автоматический деплой ещё
реализуется по плану; первый полный комплект из `main` собран и проверен на этапе 2.

Подробные настройки и ограничения описаны в
[руководстве по production-контейнерам](../docs/guides/production-containers.md).
Статус реализации и оставшиеся проверки находятся в
[плане деплоя](../docs/plans/production-deployment.md).

## Первичная конфигурация VPS

`production/server/prepare-config.mjs` читает `database.env.example`,
`migrator.env.example` и `api.env.example` из каталога шаблонов. Скрипт создаёт
`database.env`, `migrator.env`, `api.env` и `database-init.sql` в каталоге конфигурации.
Первый аргумент задаёт каталог конфигурации (по умолчанию `/config`), второй —
шаблонов (по умолчанию `/templates`). Используйте шаблоны из `runtime/env/`
переданного комплекта релиза.

Скрипт подставляет разные случайные пароли и имена пользователей PostgreSQL
для администратора, мигратора и API. Остальные параметры берутся из шаблонов;
у URL подключения сохраняются хост, порт, имя БД и параметры. SQL предназначен
для первичной установки в пустую БД `stageby` перед миграциями.

Запускайте скрипт на VPS от root через Node.js в образе API. Примонтируйте
`/etc/stageby` в `/config`, а каталог шаблонов — в `/templates` только для чтения.
Каталог конфигурации получает права 0700, файлы — 0600. Существующие файлы
не перезаписываются, секреты не выводятся. S3 credentials замените в `api.env`
вручную. SQL содержит секреты и хранится вместе с конфигурацией вне релиза.
Скрипт не подключается к БД и не применяет SQL или миграции.
