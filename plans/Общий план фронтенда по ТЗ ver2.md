# Общий план фронтенда по ТЗ ver2

Дата аудита: 14.10.2026.

Источник требований: [ТЗ на разработку страницы и сценарии edited.ver2.md](<ТЗ на разработку страницы и сценарии edited.ver2.md>).

План составлен по текущему исходному коду фронтенда и требованиям первой итерации. `[x]` означает наличие реализации, `[ ]` — оставшуюся работу или непроведённую сквозную проверку. Наличие реализации не заменяет приёмку в браузере и проверку с настоящим API.

Существующие тесты фронтенда проходят: **44 файла, 248 тестов** (`corepack pnpm --dir web run test`).

После реализации плана 01 от 14.10.2026: полный прогон Vitest — **49 файлов, 276 тестов**; после добавления двух проверок ошибок входа повторно пройдены все **6 сценариев навигации**. Состояние после планов 02–04 от 14.10.2026: запрос сброса пароля реализован; список мастера и базовая страница этапа реализованы и проверены на подменённых ответах API. Результаты и ограничения указаны в соответствующих планах. Сквозная приёмка с настоящим API остаётся открытой.

## 3. API и общие правила реализации

- [x] Сгенерированы клиентские операции для этапов, чек-листов, фото, счетов, нехваток, строк плана, выплат, дашборда и запроса сброса пароля. Это инфраструктура, а не готовые пользовательские сценарии.
- [x] Есть общие компоненты дат, денег, выбора мастера, документов, загрузки файлов и состояний интерфейса.
- [x] Есть форматирование дат и определение текущего дня Екатеринбурга.
- [ ] Использовать существующий клиент API; готовность каждой новой связки подтверждать сквозной проверкой.
- [ ] Агрегаты, статусы и доступ брать с сервера. Не вычислять общий факт из ограниченной детализации мастера.
- [ ] Суммы передавать в копейках, различать `null` и `0`, отрицательный остаток показывать как переплату. Неизвестный план — «Не задан», неизвестный остаток — «Не рассчитан».
- [ ] Сохранять различие ручного плана этапа, детализации выплат и расчёта обязательств к дате D.
