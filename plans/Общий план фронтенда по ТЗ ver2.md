- [x] Сгенерированы клиентские операции для этапов, чек-листов, фото, счетов, нехваток, строк плана, выплат, дашборда и запроса сброса пароля. Это инфраструктура, а не готовые пользовательские сценарии.
- [x] Есть общие компоненты дат, денег, выбора мастера, документов, загрузки файлов и состояний интерфейса.
- [x] Есть форматирование дат и определение текущего дня Екатеринбурга.
- [ ] Использовать существующий клиент API; готовность каждой новой связки подтверждать сквозной проверкой.
- [ ] Агрегаты, статусы и доступ брать с сервера. Не вычислять общий факт из ограниченной детализации мастера.
- [ ] Суммы передавать в копейках, различать `null` и `0`, отрицательный остаток показывать как переплату. Неизвестный план — «Не задан», неизвестный остаток — «Не рассчитан».
- [ ] Сохранять различие ручного плана этапа, детализации выплат и расчёта обязательств к дате D.
- [ ] В дашборде учитывать явный срок строки раньше правила окончания этапа; факт учитывать только по тому же составу обязательств и по дате оплаты не позже D. Оплата не уменьшает план.
- [ ] Получатель строки и ответственный мастер этапа независимы. Изменение текущего получателя не переписывает получателей прошлых выплат.
- [ ] Для новых действий обрабатывать конфликты версий, ограничения состояния и повторные запросы без потери ввода и создания дублей.
- [ ] После мутаций обновлять кэш затронутых экранов: этапа, объекта, списка мастера, дашборда, финансов и материалов.
- [ ] При повторном входе восстанавливать целевой экран и получать сохранённые фото с сервера. Незавершённый ввод сохранять в рамках того же пользователя, не переносить его в чужую сессию.
- [ ] Переиспользовать текущую архитектуру `pages` / `features` / `entities` / `shared`; сгенерированные файлы вручную не редактировать.

## 5. Границы и дальнейшая работа

- [x] Общий план отделён от исходного ТЗ в самостоятельный файл.
- [x] Разбить очередь на отдельные планы по фичам с конкретными изменениями, зависимостями и проверками: [11 планов](frontend-ver2/README.md).

В первую итерацию не включать согласование даты старта, новые роли, каталог инструментов, видео и остальные идеи из заключительного раздела ТЗ.

Журнал действий и автоматическое удаление фото относятся к серверу. Фронтенду нужны корректные действия и отображение результатов; отдельный экран журнала ТЗ не требует. Перенос существующих прикладных данных в новую модель не входит в эту доработку.
