# **Техническое описание программы**

Система управления малоэтажным строительством

**Введение:** данное ТЗ на разработку системы контроля строительства объектов, состоящих из восьми этапов, по каждому этапу есть сроки, ответственные, суммы, работы, отчеты, материалы, в первой итерации разрабатывается 12 экранов, и работа для руководителя (инженера сметчика) и мастера, остальные роли вынесены в следующие итерации.

### **1.1 Платформа**

* Адаптивный сайт (верстка как с компа так и с телефона). Мастер работает с телефона (макет 390 px, Chrome и Safari), руководитель — с компьютера (макет 1440 px). Нативных (мобильных) приложений в первой версии нет. Планшет тоже   
* Мастеру доступен ярлык на главный экран, который открывает его страницу или этап сразу.  
* Интеграций нет: ни ЭДО, ни CRM, ни мессенджеров. Заявка поставщику уходит по почте вне системы.

### **1.2 Роли**

| Роль | Что видит и делает |
| :---- | :---- |
| Руководитель (прораб) | Все объекты и этапы, все суммы. Создаёт объекты, назначает мастеров, ведёт счета и оплату работ, видит задачи на сегодня, ставит любые статусы материала |
| Мастер участка | Только назначенные ему этапы: проект, чек-лист с фото, приёмка материалов (ставит статусы «Доставлен» и «Есть нехватка»). Суммы общей не видит, но видит суммы в рамках своего этапа |

Клиент, поставщик, инженер-сметчик и приёмщик в первой версии в системе не работают. Инженер-сметчик и приёмщик будут добавлены в следующей итерации. Если приёмщик съездил на объект и проверил, результат в системе вносит руководитель.

### **1.3 Сквозные правила**

* **Этапы:** фиксированный справочник из 8 типов с одинаковыми названиями для всех проектов: фундамент, стены, крыша, окна, фасад, электрика, штукатурка, отопление (в будущем может измениться; справочник правит администратор вне интерфейса первой версии). Этапы идут последовательно, часть можно вести параллельно (окна, крыша) — это руководитель отмечает вручную по каждому этапу.  
* **Пункты чек-листа:** фиксированный шаблон на каждый тип работ. При создании объекта пункты можно добавить, переименовать или убрать. Правка действует только на этот объект, шаблон не меняется.  
* **Готовность этапа, %:** отмеченные пункты ÷ все пункты × 100, вес пунктов равный, округление до целого. Пример: 2 из 4 \= 50%.  
* **Фото:** минимум 1 на пункт, максимума нет. Форматы JPEG, PNG, HEIC, сжатие перед отправкой. Хранение 1 год с даты загрузки, затем автоудаление.  
* **Деньги:** только рубли, формат «1 800 000 ₽». Суммы видит только руководитель. Даты в формате ДД.ММ.ГГГГ.  
* Журнал действий: кто, что и когда изменил (статус, отметка пункта, фото, сумма, срок) **не ведется** (не обсуждалось, следующие итерации).  
* **Связь на площадке нестабильна:** загрузка фото с повтором, введённые данные не теряются.  
* **Уведомления:** внутри системы (блок «Задачи на сегодня»). Уведомления в чаты в другой итерации, не в этой версии.  
* **Статусы материала:** «Выставлен счёт» появляется при загрузке счёта, «Оплачен» ставит только руководитель, «Доставлен» и «Есть нехватка» ставит мастер или руководитель.  
* **Счета:** загружаются файлом в двух форматах, PDF или Jpeg.

### **1.4 Модель статусов этапа**

| Из | В | Кто | Условие |
| :---- | :---- | :---- | :---- |
| Создан | Назначен | Руководитель | Выбран мастер |
| Назначен | Укомплектован | Система | По всем счетам этапа отмечено «Доставлен» |
| Укомплектован | В работе | Система | Мастер отметил первый пункт чек-листа, фиксируется фактическая дата старта. Начать можно и без «Укомплектован» с предупреждением: материалы иногда докупаются в процессе |
| В работе | Приёмка | Система | Все пункты чек-листа отмечены (100%), этап переходит на приёмку автоматически |
| Приёмка | Выполнен | Руководитель | Все пункты подтверждены, акт оформлен |
| Приёмка | Доработка | Руководитель | Есть замечания. Комментарий обязателен, новый срок по умолчанию \+2 дня |
| Доработка | Приёмка | Система | Все помеченные пункты снова отмечены |
| Выполнен | Выплачен | Руководитель | Остаток к выплате по этапу равен 0 |

Отображение у мастера: «Ожидает» \= Создан, Назначен, Укомплектован. «В работе» \= В работе, Приёмка, Доработка. «Завершён» \= Выполнен, Выплачен.

### **3.4 Создание объекта** 

**Прототип:** панель справа на Dashboard (520 px). Открывается по «+ Создать объект». Два шага, чтобы создать объект быстро и не перегружать панель.

**Шаг 1 «Объект»**

| Поле | Правила |
| :---- | :---- |
| Клиент | Обязательное, текст до 150 знаков |
| Адрес | Обязательное.  |
| Координаты | Обязательное. Формат «55.7558, 37.6176», можно поправить вручную. Нужны для ссылки на карту |
| Проект (чертёж) | PDF целиком, один или несколько файлов, до 50 МБ каждый. Загружается один раз и виден на всех этапах. Необязателен: без него у этапов предупреждение «Проект не загружен» |
| Сроки проекта | Дата начала и окончания, в две строки, обязательные, окончание не раньше начала  |

**Шаг 2 «Этапы и сроки»**

* По умолчанию включены все 8 этапов со стандартными пунктами. Галочка включает или исключает этап.  
* По клику на название этапа раскрываются пункты: переименовать, удалить, добавить свой. На включённом этапе минимум 1 пункт.  
* Для каждого этапа: даты старта и окончания (внутри сроков проекта), флаг «может идти параллельно».  
* Мастера и плановые суммы можно указать сразу или позже на странице объекта и в блоке «Оплата работ». Обязательны при создании только клиент, адрес, сроки проекта и минимум один этап.

| № | Сценарий | Шаги | Ожидаемый результат |
| :---- | :---- | :---- | :---- |
| 1 | Быстрое создание | Клиент, адрес, координаты, сроки, «Создать» | Объект со всеми этапами и шаблонными пунктами, статус «Создан», панель закрывается, в списке новая строка |
| 2 | Исключить этап | Снять галочку | Этап не создаётся и не участвует в расчётах, «N из K» считается по включённым |
| 3 | Правка чек-листа | Раскрыть этап, удалить или добавить пункт | Правка только для этого объекта, шаблон не меняется, проценты считаются по новому списку |
| 4 | Ошибки заполнения | Пустой клиент или адрес, окончание раньше начала, этап без пунктов | Поля подсвечены, «Создать» не сохраняет, ошибка у каждого поля |
| 5 | Закрытие с данными | «Отмена» или клик по затемнению после ввода | «Отменить создание? Введённые данные будут потеряны» |
| 6 | Неверный файл проекта | Не PDF или файл больше лимита | Понятное сообщение, файл не добавляется, остальная форма сохраняется |
| 7 | Сбой сети | Обрыв при сохранении | Данные формы остаются, кнопка «Повторить», дубль не создаётся (повторный клик безопасен) |

**Расхождения с прототипом:** нет дат, мастеров, сумм и параллельности.

### **3.5 Объект / «Этапы» (P0) \- список этапов по одному объекту** 

**Прототип:** Home, 390×844. Страница всего объекта для руководителя: он видит все этапы объекта и управляет ими. Сметчик появится в следующей итерации.

**Состав экрана по порядку**

* Шапка: ФИО (для мастера), адрес, координаты и ссылка «Открыть на карте →» (по координатам, при их отсутствии по адресу, при отсутствии обоих ссылка скрыта) Дата старта и завершения.  
* Карточка «Проект (PDF)»: открыть проект целиком.  
* Карточки этапов: «Этап N · Название», бейдж статуса, сводка (материалы есть/требуется оплата/счет оплачен, чек-лист), шкала и % готовности по пунктам чек-листа. Суммы «План / Факт». План по всем этапам и факт, материалы+работы отдельно и итог.  Эта карточка не настраиваемая, она наполняется автоматом.  
* Отражаются по порядку список этапов, под каждым этапом есть дата начала, дата окончания, фио мастера, причем мастера мы выбираем из пользователей, чтоб система понимала кому этот этап можно смотреть. При нажатии на этап открывается страница этапа, первой карточкой на ней чек-лист, при нажатии на пункт чек-листа фото, или знак подгрузки фото.   
* У каждого этапа отражается статус, сумма плановая за работу,  плановая за материал. Фактическая за работу, фактическая за материал. Суммы вносит руководитель.  
* К полю материал идет возможность подгрузки счета (PDF или Jpeg), и обязательно ввод суммы счета.  
* К счету есть поле комментарий, и подсказка для мастера, указать расхождения.  
* У материалов есть статусы: выставлен счет, оплачен, доставлен. Плюс статус «Есть нехватка». «Оплачен» ставит руководитель, «Доставлен» и «Есть нехватка» ставит мастер или руководитель. Фото не подгружается по материалам (другая итерация)

### **3.6 Оплата работ (блок на странице этапа, P0, нет в прототипе)**

**Требование заказчика:** для каждой бригады свои плановые и фактические суммы выплат, платёж можно дробить. **Доступ:** руководитель. **Размещение:** блок «Оплата работ» внутри «Страницы этапа», виден и меняется только руководителем. Итоги по этапу — четыре суммы.

**Данные:** мастер, плановая сумма, срок оплаты (по умолчанию дата окончания этапа), платежи (дата, сумма, комментарий), плановая сумма материалов.

* Факт по строке \= сумма платежей. Остаток \= план − факт.  
* **План этапа** \= планы работ \+ планы материалов. **Факт этапа** \= платежи бригадам \+ оплаченные счета.  
* План за материал руководитель вносит вручную, факт за материал тоже вносится вручную.

| № | Сценарий | Шаги | Ожидаемый результат |
| :---- | :---- | :---- | :---- |
| 1 | Заполнить этап  плановыми показателями | Добавить фио мастера, сумму и срок | Строка добавлена, остаток равен плану, сумма попадает на «Дашборд» |
| 2 | Частичная оплата | Добавить платёж меньше плана | Остаток пересчитан, на «Дашборде» уменьшилось |
| 3 | Дробление платежа | Несколько платежей на одну строку (аванс, по факту) | Факт равен их сумме, история платежей списком |
| 4 | Полная оплата | Остаток равен 0 | Остаток равен 0, система может переводит этап в статус «Выплачен» |
| 5 | Переплата | Платёж больше остатка | Отражается переплата |
| 6 | Неверная сумма | Ноль, отрицательное, не число | Ошибка в поле, сохранение заблокировано |

### **3.7 Чек-лист (P1)**

**Прототип:** Checklist. Шапка со шкалой и «n из m пунктов · %». Пункты списком: чекбокс, название, подпись «Фото приложено» или «Нет фото — нельзя отметить пункт».

### **3.9 Материалы и счёт (P1)**

**Прототип:** Materials. Решения: заказ делается **по одному этапу**, каталога позиций нет, приёмка идёт одним комментарием по счёту.

**Что видит мастер:** карточку счёта (PDF, Jpeg), статусы материала «Доставлен» и «Есть нехватка», поле комментария. Суммы за материал и работу своего этапа мастер видит для просмотра. Статусы «Доставлен» и «Есть нехватка» мастер ставит сам, «Оплачен» ставит только руководитель, «Выставлен счёт» появляется при загрузке счёта.

**Что делает руководитель**

1. Формирует заявку на материалы вне системы, когда получает счет, то подкрепляет его к этапу. До подкрепления счета отмечает статус "оплатить счет".  
2. Загружает счёт (PDF или Jpeg), вводит итоговую сумму, оба поля обязательны.  
3. Отмечает «Счёт оплачен» с датой. Эти данные идут в факт за материал на странице объекта и на «Дашборд».  
4. На этап допускается несколько счетов (два поставщика), приёмка отмечается по каждому.

| № | Сценарий | Шаги | Ожидаемый результат |
| :---- | :---- | :---- | :---- |
| 1 | Счёта ещё нет | Мастер открывает «Материалы и счёт» | «Счёт ещё не загружен», переключатели недоступны |
| 2 | Загрузка счёта | Руководитель добавляет счёт (PDF или Jpeg) и сумму | Счёт виден мастеру, сумма прописана в отдельном поле и попадает в плановые платежи на «Дашборде» |
| 3 | Доставлен | Мастер или руководитель выбирает «Доставлен» | Приёмка счёта отмечена. Когда закрыты все счета этапа, статус «Укомплектован» |
| 4 | Нехватка | Мастер или руководитель выбирает «Есть нехватка» и пишет комментарий | Комментарий обязателен (до 500 знаков). У руководителя красный статус объекта и задача «Проверить нехватку» |
