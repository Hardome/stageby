## API и интерфейсы

`getStage`, `getStageChecklist`, `updateStage`, `getFileContent`.

## Контекст API

Обновлённый ответ `Stage` предоставляет `projectDocumentFileIds`, `projectPlannedStartDate`, `projectPlannedEndDate`, `assignee.phone`, `includedStageNumber` и `includedStageCount`. Этот контекст доступен руководителю и назначенному мастеру непосредственно по `getStage`; `getProject` для мастера не используется. PDF открывается через `getFileContent`. Сообщение «Проект не загружен» показывается только при успешно полученном пустом массиве документов; ошибки загрузки отображаются отдельно. `position` — позиция типа, а не номер среди включённых этапов. После изменения проекта обновляются данные этапа.

## Проверки и критерии готовности

- [x] Доступ по ролям, недоступный этап, снятие назначения.
- [x] Независимая очистка дат; планы `null` и `0`.
- [x] Конфликт версии сохраняет ввод.
- [x] Ограничения плана выплаченного этапа.
- [x] Предупреждение не блокирует работу.
- [x] PDF, телефон, границы дат и номер этапа проверены в браузере по доступному контексту `Stage`.

Обновлённый контекст `Stage` используется в UI: PDF открывается через `getFileContent`, телефон и номер среди включённых этапов показываются, даты проекта доступны для проверки. Браузерные проверки обеих тем и ширин 390/768/1024/1440 px выполнены. Сквозное прохождение остальных сценариев приложения учитывается планом 11.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.

## Результат реализации

Реализованы отдельные фичи просмотра и редактирования, серверный контекст этапа, просмотр чек-листа с предупреждениями, PDF, финансовые итоги и навигация по роли. После конфликта версии сохраняется изменённый ввод, нетронутые поля обновляются из свежего ответа. Полные сценарии чек-листа, фото, счетов и выплат остаются в планах 06–09.

Проверены обе темы и ширины 390/768/1024/1440 px на тестовых ответах API, клавиатурный фокус и отсутствие горизонтального переполнения. Общая проверка Biome обнаруживает существующие ошибки форматирования за пределами изменений; изменённые файлы проходят отдельно.

Автоматические проверки: 57 файлов тестов / 328 тестов прошли; TypeScript, ESLint, Steiger, Stylelint, сборка Vite и cspell изменённых файлов прошли. Biome изменённых файлов — без ошибок.
