# 02. Запрос сброса пароля

Приоритет: P0 / сквозные требования первой итерации.

Источник: [ТЗ ver2](<../ТЗ на разработку страницы и сценарии edited.ver2.md>), §3.1, §3.2.

[Общий план](<../Общий план фронтенда по ТЗ ver2.md>) · [Оглавление](README.md)

## Текущее состояние

- [x] Реализованы публичный запрос сброса пароля, отметки в таблице, мобильной карточке и редакторе пользователя, обновление данных после назначения пароля руководителем.

## Зависимости

Существующие вход и управление пользователями; [план 01](01-access-and-navigation.md) задаёт общую навигацию.

## Цель

Пользователь запрашивает помощь, руководитель видит запрос и назначает новый пароль.

## Изменения

- [x] Добавить ссылку «Забыли пароль» и публичную страницу `/password-reset` с полем логина.
- [x] Использовать контрактную схему; после `202` показывать одинаковое подтверждение для любого логина.
- [x] Обработать ошибки валидации, сети и ограничения запросов; исключить повторную отправку во время ожидания.
- [x] По `passwordResetRequestedAt` показывать отметку запроса в таблице, мобильной карточке и редакторе пользователя.
- [x] После назначения пароля обновлять список и карточку; подсветку снимать по актуальным серверным данным.
- [x] Передачу нового пароля пользователю оставить вне приложения.

## API и интерфейсы

`requestPasswordReset`, существующие чтение пользователей и `setUserPassword`. Новые серверные операции не нужны.

## Проверки и критерии готовности

- [x] Одинаковый результат для активного, неизвестного и отключённого логина.
- [x] Подсветка существует до назначения пароля и исчезает после успеха.
- [x] Неудачная смена пароля сохраняет отметку запроса.
- [x] Ошибка сети сохраняет логин, повтор не создаёт лишних действий.

- Vitest: 51 файл, 296 тестов прошли, включая 15 новых сценариев запроса сброса и смены пароля. Ответы API в этих сценариях подменены; проверена клиентская обработка контрактных ответов.
- ESLint, TypeScript, Stylelint, Steiger и Vite build прошли. Cspell новых файлов прошёл.
- Biome изменённых файлов прошёл. Общая проверка обнаружила 55 существующих ошибок форматирования в файлах вне этого изменения.
- В браузере проверены публичная форма, отметки в таблице и мобильной карточке в обеих темах на ширинах 390/768/1024/1440 px, отметка в редакторе и клавиатурный фокус. Горизонтального переполнения нет. Данные пользователей для визуальной проверки подменены.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
