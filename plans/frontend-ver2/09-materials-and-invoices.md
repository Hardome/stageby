## API и интерфейсы

Список/создание счетов, `updateMaterialInvoice`, создание/устранение нехватки, загрузка файлов. Изменения версионируемых ресурсов используют `expectedVersion`. Оплата и доставка независимы.

Реализовано 16.10.2026. Полный прогон Vitest: **74 файла, 425 тестов**; ещё **3 проверки в двух новых файлах** прошли отдельно. TypeScript, Biome, ESLint, Steiger, cspell и production-сборка Vite прошли. Для запуска Vite в текущем окружении использован `--configLoader native`: стандартная загрузка конфигурации не смогла собрать нативную зависимость Tailwind. Vitest запущен вне песочницы из-за `spawn EPERM`.

С подменёнными ответами API в браузере проверены обе темы, ширины 390/768/1024/1440 px без горизонтального переполнения, клавиатурный фокус, пустой список, лимит, права мастера, загрузка PDF с повтором, запрет нулевой суммы, открытие файла через авторизованный запрос, снятие оплаты и доставка уже начатого этапа. Vitest покрывает JPEG, проверки файлов/сумм/комментариев, независимость оплаты, версии, конкурентный лимит, сохранение реквизитов при потере ответа и отдельное устранение нехватки. Серверная атомарность и отсутствие дублей при реальном обрыве требуют сквозной приёмки.

## Общие правила

16.10.2026: интерфейс переработан. Сводка плана, фактической оплаты и остатка показана над списком. В карточке счёта выделены отдельные блоки оплаты и доставки; добавление, редактирование оплаты и сообщение о нехватке открываются в диалогах. Открытые нехватки видны сразу, устранённые свёрнуты в историю. В браузере с подменёнными ответами API проверены обе темы, ширины 390/768/1024/1440 px, диалоги и возврат фокуса, валидация, закрытие после успешного сохранения и отсутствие PATCH без изменений. 24 теста материалов, TypeScript, Biome, ESLint, Steiger и cspell прошли.

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
