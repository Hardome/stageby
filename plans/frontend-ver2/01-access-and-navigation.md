## Текущее состояние

- [x] Есть авторизация, проверка сессии, защита страниц, выход и обработка ошибок. Вход восстанавливает внутренний целевой URL; `/` оставлен руководителю, мастер направляется на `/my-stages`.

## Зависимости

Нет; окончательная проверка переходов — после планов 03–05.

## Цель

Открыть пользователю нужную главную и вернуть его на исходный экран после повторного входа.

## Изменения

- [x] Оставить `/` главной руководителя; мастера направлять на `/my-stages`. Удалить неактуальное название главной «Мои задачи».
- [x] Добавить в страницу входа проверяемый параметр `returnTo`: только внутренний адрес приложения, без переходов на внешние сайты.
- [x] При обращении без сессии сохранять текущие путь и параметры URL; после входа использовать `returnTo`, иначе главную по роли.
- [x] Разделить завершение сессии из-за `401`, явный выход и смену пользователя. Кэш чужих данных очищать во всех случаях; восстановление черновика разрешать только тому же пользователю.
- [x] При `403` обновлять сведения о пользователе и показывать отказ в доступе. Недоступный этап возвращает понятный экран с кнопкой на главную.
- [x] Предусмотреть сохранение ввода форм при истечении сессии без хранения паролей. Очередь выбранных фото реализуется в [плане 08](08-checklist-photos.md).

Реализация фронтенда завершена 14.10.2026. `/my-stages` пока содержит заголовок страницы; список реализуется в плане 03. `/stages/$stageId` проверяет ID и серверный доступ, показывает основные сведения и обрабатывает `403`/`404`; полный рабочий экран реализуется в плане 04. Дашборд остаётся задачей плана 05.

Черновики создания и редактирования объекта и пользователя сохраняются в текущей вкладке, проверяются схемами и разделяются по ID пользователя. После успешного сохранения или явного выхода черновик удаляется; при входе другим пользователем удаляются прежние черновики. Пароли и выбранные файлы не сохраняются. Черновик редактирования объекта привязан к версии объекта.

- [x] Отклонение внешнего `returnTo`; недоступная ссылка после смены роли — Vitest.
- [x] Повторный вход тем же пользователем и другим пользователем; явный выход очищает черновики — Vitest жизненного цикла сессии, владельца черновиков и восстановления формы.
- [x] Неверные данные и ограничение попыток — сообщения для `401` и `429` проверены в форме входа.

## Требование безопасности

Неверные данные входа и отключённый аккаунт намеренно не различаются: сервер возвращает одинаковый `401`, фронтенд показывает единое сообщение «Неверный логин или пароль.». Это согласованное требование безопасности. Отдельное сообщение «Обратитесь к руководителю» исключено из требований; изменение API для различения этих случаев не требуется.

- [x] Показывать единое сообщение для неверных данных и отключённого аккаунта, не раскрывая состояние аккаунта и не определяя его по косвенным признакам. Общая обработка `401` реализована; сообщение проверено в сценарии формы входа.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
