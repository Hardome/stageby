## Текущее состояние

- [x] Есть авторизация, проверка сессии, защита страниц, выход и обработка ошибок. Главная пока общая, целевой адрес после входа не восстанавливается.

## Зависимости

Нет; окончательная проверка переходов — после планов 03–05.

## Цель

Открыть пользователю нужную главную и вернуть его на исходный экран после повторного входа.

## Изменения

- [ ] Оставить `/` главной руководителя; мастера направлять на `/my-stages`. Удалить неактуальное название главной «Мои задачи».
- [ ] Добавить в страницу входа проверяемый параметр `returnTo`: только внутренний адрес приложения, без переходов на внешние сайты.
- [ ] При обращении без сессии сохранять текущие путь и параметры URL; после входа использовать `returnTo`, иначе главную по роли.
- [ ] Разделить завершение сессии из-за `401`, явный выход и смену пользователя. Кэш чужих данных очищать во всех случаях; восстановление черновика разрешать только тому же пользователю.
- [ ] При `403` обновлять сведения о пользователе и показывать отказ в доступе. Недоступный этап возвращает понятный экран с кнопкой на главную.
- [ ] Предусмотреть сохранение ввода форм при истечении сессии без хранения паролей. Очередь выбранных фото реализуется в [плане 08](08-checklist-photos.md).

## API и интерфейсы

`login`, `logout`, `getCurrentUser`; изменение клиентского интерфейса очистки сессии с указанием причины.

## Проверки и критерии готовности

- [ ] Вход обеими ролями; прямая ссылка без сессии; сохранение search-параметров после входа.
- [ ] Отклонение внешнего `returnTo`; недоступная ссылка после смены роли.
- [ ] Повторный вход тем же пользователем и другим пользователем; явный выход очищает черновики.
- [ ] Неверные данные и ограничение попыток.

## Внешнее ограничение

Сервер одинаково возвращает `401` для неверных данных и отключённого пользователя. Отдельное сообщение «Обратитесь к руководителю» невозможно достоверно показать без различимого ответа API. Этот пункт оставить незавершённым, не определять отключение по косвенным признакам.

- [ ] Проверить отдельное сообщение отключённому пользователю после устранения внешней зависимости.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
