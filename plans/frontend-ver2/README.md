## Порядок реализации

14.10.2026: реализован план 01 — главные по роли, безопасный `returnTo`, возврат после входа, очистка кэша и сохранение черновиков только для того же пользователя, отказ в доступе с переходом на главную. Маршруты списка мастера и этапа подготовлены; их полное содержимое относится к планам 03–04. По согласованному требованию безопасности неверные данные входа и отключённый аккаунт получают одинаковый `401` и единое сообщение; зависимость от различимого ответа API снята. Приёмка в браузере с настоящим API ещё не проведена.

**01–02 → 03–04 → 05–06 → 07–09 → 10 → 11.**

- Доступ и навигация задают стартовые страницы и повторный вход.
- Список мастера и базовая страница этапа дают точки входа в остальные сценарии.
- Дашборд и финансовые действия используют данные этапа.
- Полное выполнение чек-листа требует экрана фото из плана 08.
- Приёмка и доработка требуют рабочего чек-листа и фото.
- Подтверждение выплаты реализуется только в плане 06; приёмка принадлежит плану 10. Блок оплаты можно разработать раньше и проверить на готовом этапе, сквозной сценарий — после плана 10.
- Сквозная приёмка выполняется после реализации всех фич и устранения внешних блокеров.

Номера задают рекомендуемую очередь, а не запрещают независимую работу. Конечные переходы дашборда проверяются после создания экранов чек-листа и материалов.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты — в `app/routes`, сборка экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`.
- Проверять ID до запросов. Состояние списков и дату дашборда хранить в URL.
- Не смешивать начальную загрузку, пустой результат, ошибку и фоновое обновление.
- При ошибках сохранять ввод; конфликт версии требует обновления данных.
- Серверные статусы и агрегаты не заменять клиентскими догадками.
- Деньги передавать в копейках, различать `null` и `0`, показывать отрицательный остаток.
- После мутаций обновлять затронутые запросы, не раскрывать данные прежней сессии.
- Проверять светлую и тёмную темы, клавиатурный фокус, ширины 390/768/1024/1440 px.
- Генерируемые файлы вручную не редактировать; комментарии в коде писать по-русски.

## Выбранные значения по умолчанию

- [x] По требованию безопасности неверные данные входа и отключённый аккаунт не различаются: одинаковый `401` и сообщение «Неверный логин или пароль.». Отдельное сообщение отключённому пользователю исключено. См. [план 01](01-access-and-navigation.md).
- Главная руководителя — `/`, мастера — `/my-stages`.
- Этап — `/stages/$stageId`; чек-лист — `/stages/$stageId/checklist`; фото — `/stages/$stageId/checklist/$itemId/photos`; материалы — `/stages/$stageId/materials`.
- Запрос сброса пароля — `/password-reset`.
- Список этапов мастера — страницы по 20 записей.
- Подготовка фото — длинная сторона до 2560 px, качество JPEG 0,85; HEIC конвертируется на клиенте. Читаемость проверить на реальных фото.
- Очередь незавершённых фото — IndexedDB, с разделением по пользователю и пункту; при отказе хранилища — память текущей вкладки с предупреждением.
- Ярлык запускает `/`; полноценный автономный режим и фоновая загрузка при закрытом приложении не входят в объём.
