## Изменения и приёмка

- [x] Пройти полный цикл обеими ролями с настоящим API: создание → назначение → счета → выполнение с фото → приёмка/доработка → выплаты → завершение.
- [x] Проверить независимые даты, нулевые и незаданные планы, строки выплат, переплату, финансовый расчёт на D. Даты и планы проверены через HTTP, расчёт на D дополнительно покрыт интеграционными тестами API на временной БД.
- [x] Проверить исключение и восстановление этапов, включая историю удалённых фото; конфликт общего сохранения не сохраняет часть формы.
- [x] Проверить допустимые и запрещённые изменения выплаченного этапа, сохранение получателей и фактических дат.
- [x] Проверить прямые ссылки, истечение сессии, снятие назначения, смену пользователя и отсутствие чужих данных.
- [x] Добавить manifest, иконки и [инструкцию установки ярлыка](../../docs/install-shortcut.md). Старт ярлыка — `/`; роль и сохранённая сессия определяют нужную страницу. Прямую ссылку на этап можно добавить отдельным ярлыком средствами браузера.
- [x] Сервис-воркер и полноценный автономный режим не добавлять: требуется ярлык и устойчивые повторы загрузки. Реальный сбой PUT, восстановление IndexedDB после перезагрузки и успешный повтор проверены.
- [ ] Проверить мобильные Chrome и Safari, ширины 390/768/1024/1440 px, обе темы, PDF, камеру, HEIC, фокус и отсутствие горизонтального переполнения.

  - [ ] Физические Android Chrome и iOS Safari: камера, реальные HEIC, читаемость фото, установка и сохранение сессии при запуске ярлыка.
- [x] Выполнить проверки фронтенда и регрессионную Vitest-серию. Серверные проблемы фиксировать отдельными зависимостями. Подтверждённых блокирующих серверных дефектов не найдено.

## Критерий готовности

Выполнить сквозные сценарии после реализации планов 01–10; локальные проверки отдельных экранов не заменяют полный цикл. Проверять и фиксировать фактические ошибки API или приложения по результатам приёмки.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
