## Цель

Заменить временный список управленческой сводкой.

## Изменения

- [ ] Реализовать страницу руководителя на `/`, сохранив создание объекта и возврат после создания.
- [ ] Хранить `through` и `offset` в URL; по умолчанию использовать сегодня по Екатеринбургу.
- [ ] Ограничить календарь сегодня…+30 дней включительно. Для недопустимой даты показывать «Расчёт недоступен», не отправляя запрос расчёта.
- [ ] Загружать `getDashboardSummary` и `listDashboardProjects` независимо.
- [ ] Показать число активных объектов и план/факт/остаток по трём категориям; использовать серверные значения без повторного расчёта финансов.
- [ ] Таблицу строить по серверному `selectedStage`; порядок строк сохранять серверный.
- [ ] Название объекта ведёт на объект. Счёт, мастер и статус ведут соответственно на материалы, параметры этапа и чек-лист; эти действия открывать в отдельной вкладке.
- [ ] При отсутствии выбранного этапа показывать «—», статус завершённого объекта и отсутствие действий этапа.
- [ ] Добавить предупреждение о неназначенном мастере при заданном старте и оставшихся семи днях или меньше.
- [ ] Реализовать общий индикатор материалов с настоящим жёлтым состоянием; использовать существующую палитру и текстовые подписи вместо обозначения только цветом.
- [ ] Переиспользовать индикатор на объекте, этапе и экране материалов.

## API и интерфейсы

`getDashboardSummary`, `listDashboardProjects`. Суммы строки объекта и суммы выбранного этапа не смешивать. Общий компонент индикатора материалов открыть через публичный API сущности; новые цветовые роли строить на текущей палитре.

## Проверки и критерии готовности

- [ ] Границы календаря, смена даты, обновление страницы и пагинация.
- [ ] Независимый отказ карточек и таблицы.
- [ ] Неизвестный план, ноль, переплата и пустой расчёт.
- [ ] Первый невыплаченный этап остаётся выбранным до выплаты; после выплаты все ссылки переключаются вместе.
- [ ] Создание объекта и дополнительный этап обновляют активный счётчик.
- [ ] Строки без старта и полностью завершённые объекты.
- [ ] Выбор одного этапа для всех индикаторов и правильные целевые ссылки.

## Общие правила

- Использовать существующие React, TanStack Router/Query, React Hook Form, контрактные схемы и UI-компоненты.
- Маршруты размещать в `app/routes`, сборку экранов — в `pages`, действия — в отдельных фичах с публичным `index.ts`. Общие данные этапа, права и инвалидирование запросов — в `entities/stage`, когда появится повторное использование.
- Проверять идентификаторы до запроса. Состояние списков и выбранную дату дашборда хранить в URL.
- Показывать начальную загрузку, пустое состояние, ошибку с повтором и фоновое обновление. При ошибке сохранения сохранять ввод; конфликт версии требует обновления данных.
- Использовать серверные статусы и агрегаты. Деньги передавать в копейках, `null` отличать от нуля, отрицательный остаток показывать как переплату.
- После действий обновлять затронутые запросы этапа, чек-листа, материалов, выплат, объекта, списка мастера и дашборда.
- Проверять светлую и тёмную темы, клавиатурный фокус и ширины 390/768/1024/1440 px.
- Генерируемые файлы обновлять через кодогенерацию. Комментарии в коде писать по-русски.
- Серверные доработки не входят в эти планы. Недостающие данные API фиксировать как внешнюю зависимость, не заменять вымышленными данными.
