# Дополнительный этап объекта (§3.5)

Зависимость: завершён [план редактирования объекта](frontend-project-edit.md), доступны форма редактирования и атомарное сохранение. Отмечать выполненное `[x]`.

## Добавление и восстановление

- [ ] На последнем экране добавить единственный «Дополнительный этап» с фиксированным названием и пустым чек-листом.
- [ ] Восстанавливать ранее исключённый дополнительный этап по ID; повторное добавление блокировать.
- [ ] Разрешить добавление дополнительного этапа к завершённому объекту.
- [ ] Использовать общие поля этапа и редактор чек-листа; перед сохранением требовать минимум один пункт у включённого этапа.

## Атомарное сохранение

- [ ] Передавать новый этап через additionalStage в одном частичном PATCH через useUpdateProject вместе с остальными изменениями формы и версиями ресурсов.
- [ ] При восстановлении сохранять ID и историю существующего этапа.
- [ ] Подключить обработку ошибок полей, конфликтов версий, сохранение ввода и защиту от двойного сохранения из формы редактирования.
- [ ] Для архивного объекта отключить редактирование с объяснением.
- [ ] После сохранения обновить кэш объекта, инвалидировать редактор, списки, затронутые чек-листы и дашборд; вернуться на просмотр и показать уведомление об успехе.

## Проверки

- [ ] Проверить создание, восстановление и запрет дублирования дополнительного этапа.
- [ ] Проверить добавление к завершённому объекту и запрет редактирования архивного объекта.
- [ ] Проверить фиксированное название, начальный пустой чек-лист и требование минимум одного пункта перед сохранением.
- [ ] Проверить additionalStage в общем PATCH, сохранение ID при восстановлении, ошибки полей и конфликты версий.
- [ ] Проверить сохранение ввода, защиту от двойного сохранения, возврат на просмотр и обновление кэша.
- [ ] Проверить обе темы и ширины 390, 768, 1024 и 1440 px.
- [ ] Запустить Biome, ESLint, Stylelint, Steiger, TypeScript, Vitest и сборку web.

API и схемы остаются действующими.
