# План реализации и проверки страницы создания проекта

## Основание и порядок проверки

Цель — реализовать отдельную адаптивную страницу создания проекта (в интерфейсе ТЗ — «объекта») для руководителя по следующим документам:

- [ТЗ edited.ver2](ТЗ%20на%20разработку%20страницы%20и%20сценарии%20edited.ver2.md): §1.1–1.3, §3.4, шаблоны из §4.0.
- [Доменная модель](../docs/domain-model.md): роли, проект, типы этапов, индивидуальные чек-листы, файлы, деньги и идемпотентность.
- [Дизайн-система](../docs/design-system.md): токены, состояния, типографика, размеры и обе темы.
- [API-контракт](../docs/api-contract.md): составное создание проекта, справочники, загрузки, доступ и ошибки.
- [Web-гайдлайн](../docs/web-guidelines.md): структура frontend, формы, интеграция и доступность.

Аудит выполнен 05.10.2026 по текущему рабочему дереву: исходники, тесты и проверки web. Отметки по коду не означают прохождение браузерной или реальной API-интеграции; такие проверки отмечены отдельно. Отмечать `[x]` только после подтверждения всех условий пункта. Под отмеченным пунктом записывать доказательство: путь к коду, тест, результат команды или браузерный сценарий. Частично выполненный пункт оставлять `[ ]` и записывать, что осталось. Для недоступной проверки указывать причину, не отмечая её выполненной. Идентификаторы пунктов сохранять при последующих правках.

ТЗ требует после создания открыть страницу созданного объекта в той же вкладке. Возврат на главную из прежнего плана не удовлетворяет этому требованию. Полноценная реализация дашборда, страницы объекта, управления справочником и операций после создания — отдельные задачи; нужные для завершения сценария переход и обновление данных проверяются здесь. Если целевой страницы ещё нет, фиксировать это как незавершённую интеграцию.

## 5. Загрузка PDF

  - Аудит 05.10.2026: Частично: MIME/расширение, имя, размер включая ровно 50 МиБ и %PDF- проверяются. Сигнатура проверяется только в uploadDocument после добавления файла в форму, а не до добавления; см. U02.
- [ ] U02. Неверный или слишком большой файл не добавляется; пользователь видит понятную причину, остальные поля и выбранные корректные файлы сохраняются.

- [x] U03. Загрузка выполняется при выборе: SHA-256, создание upload-сессии, PUT содержимого по подписанному URL, подтверждение завершения через API. На внешний URL не передаются сессионные credentials.

- [x] U04. Для каждого файла видны имя, состояние загрузки, ошибка, повтор и удаление из формы. В запрос создания попадают только идентификаторы успешно подтверждённых файлов автора запроса.
