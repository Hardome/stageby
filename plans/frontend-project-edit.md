# Часть 2. Редактирование объекта (§3.5)

Зависимость: завершена часть 1, доступна страница просмотра объекта. Отмечать выполненное `[x]`.

## Маршрут и общая форма

- [ ] Добавить `/projects/$projectId/edit`, проверку ID и доступ руководителя.
- [ ] Подключить кнопку редактирования на странице просмотра.
- [ ] Загружать согласованный снимок через useGetProjectEdit с исключёнными этапами и версиями.
- [ ] Вынести общие части формы создания в entities/project; модели и сохранение оставить отдельными.
- [ ] Добавить заполненные экраны объекта, выбора этапов и последовательного редактирования этапов.
- [ ] Добавить «Назад», «Следующий этап», «Сохранить», «Отмена» и переход к ошибочному полю.
- [ ] Защитить выход с изменениями; фоновое обновление и ошибки не сбрасывают ввод.

## Реквизиты, документы и этапы

- [ ] Редактировать обязательные реквизиты, сроки проекта и список PDF.
- [ ] Сохранять оставшиеся PDF по ID, открывать, удалять из списка и загружать новые с повтором.
- [ ] Блокировать сохранение при незавершённых загрузках.
- [ ] Редактировать независимые nullable-даты этапов, мастеров и ручные планы работ и материалов.
- [ ] Различать null и ноль; факты и агрегаты не редактируются.
- [ ] Проверять даты внутри сроков проекта и порядок начала/окончания.
- [ ] Для выплаченного этапа запретить очистку плана работ и увеличение выше факта.
- [ ] Исключать и восстанавливать существующие этапы с сохранением ID и истории.
- [ ] Блокировать исключение последнего включённого и явно начатого этапа.
- [ ] Показывать серверные причины запрета исключения, включая счета, выплаты и историю фото.
- [ ] Не создавать отсутствующие стандартные этапы: использовать действующий контракт.

## Чек-лист и дополнительный этап

- [ ] До старта разрешить добавление, удаление, переименование, перестановку пунктов и изменение подсказок.
- [ ] После фактического старта показывать состав только для чтения.
- [ ] Требовать минимум один пункт у включённого этапа.
- [ ] На последнем экране добавить единственный «Дополнительный этап» с фиксированным названием и пустым чек-листом.
- [ ] Восстанавливать ранее исключённый дополнительный этап по ID; повторное добавление блокировать.
- [ ] Разрешить добавление дополнительного этапа к завершённому объекту.

## Атомарное сохранение

- [ ] Отправлять один частичный PATCH через useUpdateProject с версиями ресурсов.
- [ ] Передавать изменённые реквизиты, документы, этапы и чек-листы; новый этап через additionalStage.
- [ ] Не изменять строки выплат, выплаты, фактические даты и получателей прошлых платежей.
- [ ] Сопоставлять серверные ошибки полей с экранами формы.
- [ ] При конфликте версий сохранить ввод и предложить актуальный снимок с подтверждением сброса правок.
- [ ] Отключить автоматические повторы PATCH и защитить от двойного сохранения.
- [ ] Обработать потерю сессии, отсутствие прав, 404 и остальные конфликты.
- [ ] Для архивного объекта отключить редактирование с объяснением; разархивирование не входит в задачу.
- [ ] Обновить кэш объекта; инвалидировать редактор, списки, затронутые чек-листы и дашборд.
- [ ] Вернуться на просмотр и показать уведомление об успехе.

## Проверки

- [ ] Проверить заполнение, частичный PATCH, ID/версии, nullable-планы, очистку дат и сроки.
- [ ] Проверить исключение, восстановление, последний этап и серверные запреты.
- [ ] Проверить ограничения чек-листа после старта и выплаченного этапа.
- [ ] Проверить создание, восстановление и запрет дублирования дополнительного этапа.
- [ ] Проверить документы, ошибки полей, конфликт версий, сохранение ввода и защиту выхода.
- [ ] Проверить сохранение, возврат на просмотр и обновление кэша.
- [ ] Проверить обе темы и ширины 390, 768, 1024 и 1440 px.
- [ ] Обновить дерево маршрутов генерацией, сохранив существующие локальные изменения.
- [ ] Запустить Biome, ESLint, Stylelint, Steiger, TypeScript, Vitest и сборку web.

API и схемы остаются действующими. Дашборд, оплата, материалы, фото, приёмка и рабочая страница этапа — отдельные задачи.
