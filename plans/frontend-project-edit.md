# Часть 2. Редактирование объекта (§3.5)

Зависимость: завершена часть 1, доступна страница просмотра объекта. Отмечать выполненное `[x]`.

Дополнительный этап вынесен в [отдельный план](frontend-project-additional-stage.md), выполняемый после этой части.

## Маршрут и общая форма

- [x] Добавить `/projects/$projectId/edit`, проверку ID и доступ руководителя.
- [x] Подключить кнопку редактирования на странице просмотра.
- [x] Загружать согласованный снимок через useGetProjectEdit с исключёнными этапами и версиями.
- [x] Вынести общие части формы создания в entities/project; модели и сохранение оставить отдельными.
- [x] Добавить заполненные экраны объекта, выбора этапов и последовательного редактирования этапов.
- [x] Добавить «Назад», «Следующий этап», «Сохранить», «Отмена» и переход к ошибочному полю.
- [x] Защитить выход с изменениями; фоновое обновление и ошибки не сбрасывают ввод.

## Реквизиты, документы и этапы

- [x] Редактировать обязательные реквизиты, сроки проекта и список PDF.
- [x] Сохранять оставшиеся PDF по ID, открывать, удалять из списка и загружать новые с повтором.
- [x] Блокировать сохранение при незавершённых загрузках.
- [x] Редактировать независимые nullable-даты этапов, мастеров и ручные планы работ и материалов.
- [x] Различать null и ноль; факты и агрегаты не редактируются.
- [x] Проверять даты внутри сроков проекта и порядок начала/окончания.
- [x] Для выплаченного этапа запретить очистку плана работ и увеличение выше факта.
- [x] Исключать и восстанавливать существующие этапы с сохранением ID и истории.
- [x] Блокировать исключение последнего включённого и явно начатого этапа.
- [x] Показывать серверные причины запрета исключения, включая счета, выплаты и историю фото.
- [x] Не создавать отсутствующие стандартные этапы: использовать действующий контракт.

## Чек-лист

- [x] До старта разрешить добавление, удаление, переименование, перестановку пунктов и изменение подсказок.
- [x] После фактического старта показывать состав только для чтения.
- [x] Требовать минимум один пункт у включённого этапа.

## Атомарное сохранение

- [x] Отправлять один частичный PATCH через useUpdateProject с версиями ресурсов.
- [x] Передавать изменённые реквизиты, документы, этапы и чек-листы.
- [x] Не изменять строки выплат, выплаты, фактические даты и получателей прошлых платежей.
- [x] Сопоставлять серверные ошибки полей с экранами формы.
- [x] При конфликте версий сохранить ввод и предложить актуальный снимок с подтверждением сброса правок.
- [x] Отключить автоматические повторы PATCH и защитить от двойного сохранения.
- [x] Обработать потерю сессии, отсутствие прав, 404 и остальные конфликты.
- [x] Для архивного объекта отключить редактирование с объяснением; разархивирование не входит в задачу.
- [x] Обновить кэш объекта; инвалидировать редактор, списки, затронутые чек-листы и дашборд.
- [x] Вернуться на просмотр и показать уведомление об успехе.

- [x] Проверить исключение, восстановление, последний этап и серверные запреты.
- [x] Проверить ограничения чек-листа после старта и выплаченного этапа.
- [x] Проверить документы, ошибки полей, конфликт версий, сохранение ввода и защиту выхода.

API и схемы остаются действующими. Дашборд, оплата, материалы, фото, приёмка и рабочая страница этапа — отдельные задачи.

Реализовано 13.10.2026. Кнопка «Редактировать» расположена рядом с «Открыть на карте».

Проверки: 222 теста Vitest, TypeScript, ESLint, Stylelint, Steiger, cspell и сборка web прошли.
Biome прошёл на изменённых файлах; общая проверка сообщает о существующих проблемах форматирования
в остальных файлах, включая окончания строк CRLF. Интерфейс проверен в браузере на тестовом API-снимке:
светлая и тёмная темы, ширины 390, 768, 1024 и 1440 px, все три шага без горизонтального переполнения.
Проверены подтверждение выхода, сохранение правок при продолжении редактирования, частичный PATCH
и переход на просмотр после сохранения. Дополнительный этап по отдельному плану не реализовывался.
