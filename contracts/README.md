# Контракты Stageby

Самостоятельный пакет OpenAPI 3.1. Единственная прямая зависимость — `@redocly/cli`: проверка, сборка спецификации и HTML-документации. Node.js 24+ и pnpm 11+, как в остальных пакетах Stageby.

## Начало работы

Из папки `contracts`:

```sh
pnpm install --frozen-lockfile
pnpm run build
```

Из корня Stageby те же команды запускаются через `pnpm --dir contracts`.

| Команда | Результат |
| --- | --- |
| `pnpm run lint` | Проверка OpenAPI, ссылок и конфигурации Redocly |
| `pnpm run bundle` | Единая спецификация `openapi.yaml` с внутренними `$ref` |
| `pnpm run generate` | Проверка и сборка спецификации для приложений |
| `pnpm run docs` | HTML-документация `dist/index.html`, которую можно открыть в браузере |
| `pnpm run build` | Проверка, сборка спецификации и документации |

## Структура

```text
contracts/
├── openapi.yaml           # собранный контракт для API и Web, хранится в Git
├── references/
│   ├── stageby/stageby.yaml       # корневой документ и ссылки на маршруты
│   ├── common/common.yaml         # общие ошибки, параметры и безопасность
│   ├── auth/auth.yaml             # вход и сессия
│   ├── users/users.yaml           # сотрудники и исполнители
│   ├── projects/projects.yaml     # объекты строительства
│   ├── stages/stages.yaml         # этапы и приёмка
│   ├── checklists/checklists.yaml # один чек-лист на этап
│   ├── files/files.yaml           # загрузки и фото
│   ├── work-payments/work-payments.yaml # выплаты мастерам
│   ├── materials/materials.yaml   # счета и нехватки
│   └── dashboard/dashboard.yaml   # панель руководителя
├── redocly.yaml           # список API и правила проверки
├── package.json
├── pnpm-lock.yaml
└── dist/                 # результаты сборки, не хранятся в Git
```

Контракты называются по сущностям и размещаются в `references/<entity>/<entity>.yaml`. Модели находятся в `components.schemas` того же файла. Документ `references/stageby/stageby.yaml` объединяет маршруты через `$ref` и задаёт метаданные, теги и общую безопасность. Файлы сущностей являются частями этого документа, а не отдельными сервисами; по отдельности в `apis` они не регистрируются. Общие схемы переиспользуются внешними ссылками. В Redocly зарегистрирован единый API `stageby`, его результат — `openapi.yaml`.

Текущая версия: логин/пароль, учётные записи от руководителя, объекты с выбранными типами этапов,
индивидуальные чек-листы с фото, выплаты мастерам, счета и нехватки материалов, панель руководителя.
Предметные маршруты реализованы в API и покрыты интеграционными тестами.

Подробности: [предметная модель](../docs/rules/domain-model.md), [сценарии и правила API](../docs/rules/api-contract.md). Генератор документации создаёт `dist/index.html`.

## Изменение контракта

1. Измените маршруты и модели в соответствующем файле сущности. Новые пути подключите в `references/stageby/stageby.yaml`.
2. Из корня Stageby соберите контракт и обновите код приложений:

   ```sh
   pnpm run codegen
   ```

3. Если нужна HTML-документация, выполните в `contracts` команду `pnpm run docs`.

API, Web и Swagger UI читают собранный `contracts/openapi.yaml` без внешних ссылок. Этот файл хранится в Git: коммитьте его вместе с исходниками, чтобы приложения могли работать сразу после клонирования. `openapi.yaml` и сгенерированный код приложений вручную не редактируются. Документация в `dist` предназначена для просмотра и публикации.

Модели выносятся в отдельные файлы только при переиспользовании между контрактами. `operationId` должны быть уникальными и стабильными: от них зависят имена сгенерированных методов.

ID новых сущностей описываются как `integer` с `minimum: 1` и `maximum: 2147483647`,
включая параметры URL, внешние ключи и элементы массивов ID. Их назначает БД через автоинкремент.
`format: int32` не добавляем: текущий генератор Kubb теряет числовые границы при этом формате;
диапазон задаётся явно. Nullable-ID сохраняют возможность передать `null` для снятия назначения.

Для CI достаточно `pnpm install --frozen-lockfile` и `pnpm run build`; артефакты — `openapi.yaml` и `dist/index.html`. Команда `git diff --exit-code -- openapi.yaml` после сборки проверяет, что закоммиченный контракт актуален. Пакет можно вынести в отдельный репозиторий целиком: команды не зависят от соседних `api` и `web`. При таком переносе потребителям нужно передавать собранную спецификацию и обновить пути к ней.

Документация Redocly: [конфигурация](https://redocly.com/docs/cli/configuration), [bundle](https://redocly.com/docs/cli/commands/bundle), [build-docs](https://redocly.com/docs/cli/commands/build-docs).
